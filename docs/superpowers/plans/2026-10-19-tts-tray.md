# TtsTray Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WinForms-программа в трее, читающая текст из поля ввода и длинный текст из буфера обмена голосами SAPI (Microsoft + Silero).

**Architecture:** Один процесс, один UI-поток (STA). Класс `SapiSpeaker` — тонкая обёртка над одним экземпляром COM `SAPI.SpVoice` (через `dynamic`), живущим всё время работы. `MainForm` создаётся скрытой (handle есть, окно не показано), владеет `NotifyIcon`, слушает `WM_CLIPBOARDUPDATE`. `SettingsForm` — модальный диалог. Настройки — JSON в `%APPDATA%\TtsTray\settings.json`.

**Tech Stack:** .NET 10, WinForms, COM SAPI 5.4 (`SAPI.SpVoice`), `System.Text.Json`. Без NuGet-пакетов.

**Spec:** `docs/superpowers/specs/2026-10-19-tts-tray-design.md` — исполнитель читает её целиком перед своей задачей.

## Проверенные факты о SAPI на этой машине (заготовки 2026-10-19)

Это замеры, а не догадки — опирайся на них.

| Факт | Следствие для кода |
|---|---|
| `voice.GetVoices()` → токены; `token.Id` (string), `token.GetDescription()` (string), `token.GetAttribute("Language")` (`"419"` = ru-RU, hex LCID). | Голос Silero: `Id` содержит `TokenEnums\SileroTTS`. Голос Microsoft: `GetDescription()` начинается с `"Microsoft "`. Иначе — группа «Другие». |
| `voice.Speak(text, 1)` — асинхронно (`SVSFlagsAsync`). `voice.Speak("", 2)` (`SVSFPurgeBeforeSpeak`) обрывает чтение за ~50–120 мс. Флаги для «прервать и читать новое»: `3`. | — |
| `voice.WaitUntilDone(0)` — неблокирующий, `true` = чтение закончено. | Окончание чтения определять **им**, опросом по таймеру. |
| `voice.Status.RunningState` при выводе в файл возвращал `0` всегда. | **Не использовать** для логики. |
| `voice.Pause()` / `voice.Resume()` работают с Silero. | — |
| **Стоп (`Speak("",2)`) во время паузы оставляет голос на паузе: следующий `Speak` молчит, пока не вызван `Resume()`.** Пауза — счётчик: два `Pause()` требуют двух `Resume()`. | Перед каждым новым `Speak` и в `Stop`, если `IsPaused` — вызвать `Resume()` ровно один раз. `Pause()` вызывать только если ещё не на паузе. |
| `Rate` (−10…10) и `Volume` (0…100) Silero учитывает. | — |
| Длинный текст (~2700 слов) звучит потоком: первый звук через ~0,26 с. | Резать текст не нужно. |
| Первый синтез в экземпляре `SpVoice`: 2,7–8,7 с. Новый экземпляр в уже прогретом процессе: ~1,4 с. | Один `SpVoice` на всё время работы. Прогрев — на этом же экземпляре. |
| `voice.AudioOutputStream = memoryStream` → вывод в память; `voice.AudioOutputStream = null` → снова динамики (без исключения). Поток в память: `Activator.CreateInstance(Type.GetTypeFromProgID("SAPI.SpMemoryStream"))`. | Прогрев: в `SpMemoryStream`, по окончании — `null`. |

**Как выглядят молчаливые отказы здесь** (собирается и запускается, но не работает):
- после «Стоп на паузе» следующее чтение беззвучно (см. таблицу);
- обращение к `SpVoice`/`Clipboard` из потока пула — исключение `InvalidCastException`/`ThreadStateException` или зависание;
- `AddClipboardFormatListener` не вызван, потому что handle окна не создан, — автоозвучка молча не работает;
- «Озвучить» во время прогрева — звук уходит в `SpMemoryStream`, а не в динамики;
- иконка остаётся в трее после выхода, если не `notifyIcon.Visible = false` + `Dispose()`.

## Review Focus

1. Копирование длинного текста **во время паузы** → новый текст слышен (снятие паузы перед `Speak`). Проверка — задача 2, шаг 4.
2. Копирование картинки / файлов / копирование, пока буфер занят другой программой → без исключений и без чтения. Задача 2, шаг 4.
3. Одно копирование из браузера/Word шлёт несколько `WM_CLIPBOARDUPDATE` → чтение не перезапускается. Задача 2, шаг 4.
4. Битый `settings.json` или сохранённый голос удалён → программа стартует с голосом по умолчанию и показывает уведомление. Задача 1, шаг 6.
5. «Озвучить» сразу после запуска (идёт прогрев) → звук в динамиках. Задача 1, шаг 6.
