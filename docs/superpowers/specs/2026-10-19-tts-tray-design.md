# TtsTray — чтение текста голосами SAPI (Microsoft + Silero)

Дата: 2026-10-19. Статус: на согласовании.

## Зачем

Нужна маленькая программа для Windows, которая читает текст вслух качественными голосами Silero и, при желании,
стандартными голосами Microsoft. Главный сценарий — «скопировал длинный текст, и он сам зазвучал», без открытия окон.
Второй сценарий — вставить или набрать текст в окне программы и нажать «Озвучить».

Требование пользователя: **только C#, без Python и без torch в нашем коде.**

## Что уже есть на машине (проверено 2026-10-19)

- Установлен **Silero TTS SAPI 1.0.2** (`C:\Program Files\SileroTTS`, релиз v5.6 из
  github.com/snakers4/silero-models). Это готовый движок SAPI5: внутри свой libtorch (`bin\torch_cpu.dll`),
  модель `models\tts\v5_cis_base_nostress.bin`, утилита настроек `bin\silero_tts_config.exe`
  (её конфиг — `%APPDATA%\SileroTTS\config.json`: `enable_accentor`, `enable_homosolver`).
- Голоса Silero (~60: `Zinaida (Russian)`, `Aigul (Russian)`, `Dmitriy (Belarusian)` … — 20 языков) видны в SAPI через
  `HKLM\SOFTWARE\Microsoft\Speech\Voices\TokenEnums\SileroTTS\…`. Голоса Microsoft: Irina Desktop (ru), David, Zira (en).
- .NET SDK 10.0.402 установлен.

Результаты одноразовой проверки (консоль .NET 10, x64):

| Что | Результат |
|---|---|
| `System.Speech.Synthesis.SpeechSynthesizer` + голос Silero | **Не работает**: голос виден, но WAV пустой (~4 КБ). С голосом Irina — работает. |
| COM `SAPI.SpVoice` через `Type.GetTypeFromProgID` + `dynamic` | Работает для Silero и Microsoft. |
| `Speak(text, 1 /*SVSFlagsAsync*/)` + `WaitUntilDone` | Работает. |
| `Rate` у Silero | Учитывается (Rate=6 → звук вдвое короче). |
| `Volume` у Silero | Учитывается (Volume=20 → пиковая амплитуда ровно 20 % от Volume=100). |
| Длинный текст (~2700 слов, ~22 мин звука), `SVSFlagsAsync` | Звук идёт **потоком**: первые данные через ~0,26 с, синтез ~120× быстрее реального времени. Резать текст на куски не нужно. |
| Прерывание `Speak("", 2 /*SVSFPurgeBeforeSpeak*/)` во время длинного синтеза | ~50 мс. |
| `Status.RunningState` через `dynamic` при выводе в файл | Вернул `0` и во время, и после синтеза — **ненадёжно**. Для «чтение закончилось» опрашивать `WaitUntilDone(0)` (неблокирующий, `true` = закончено) или событие `EndStream`. |
| `Pause()` / `Resume()` | **Не проверено** (нужен вывод на динамики) — первая проверка в плане. Если с Silero не работает — кнопку паузы скрыть для голосов Silero. |
| Первый синтез Silero в процессе | ~8,7 с (загрузка модели); дальше быстро. |
| Отличить голос Silero от Microsoft | `token.Id` содержит `TokenEnums\SileroTTS`. |

## Цели

1. Окно с многострочным полем ввода и кнопками «Озвучить», «Пауза/Продолжить», «Стоп», «Настройки».
2. Автоозвучка буфера обмена: если скопирован текст, в котором **больше N слов** (N по умолчанию 100, настраивается),
   он читается сам. Короткие копирования игнорируются.
3. После запуска программа сразу в трее (окно не показывается).
4. Два «движка» — голоса Microsoft и голоса Silero — оба через SAPI COM `SpVoice`, в **одном списке, сгруппированном**
   на «Silero» и «Microsoft».
5. Окно настроек: голос, скорость, громкость, порог N, вкл/выкл автоозвучки, автозапуск с Windows,
   кнопка «Настройки Silero…».

## Не цели

- Свой SAPI-движок, ONNX, TorchSharp, Python — не делаем: Silero уже работает через SAPI.
- Выбор модели Silero и частоты дискретизации — их задаёт установленный движок, у нас только выбор голоса.
- Сохранение в WAV/MP3, SSML, подсветка читаемого слова, глобальные горячие клавиши, установщик — *(моё решение:
  не делаем в первой версии)*.
- Голоса OneCore (Microsoft Pavel, Mark) — `SpVoice` их не перечисляет, не добавляем.

## Анти-цели (провал, даже если «работает»)

- Автоозвучка буфера **выводит окно на передний план или крадёт фокус** у программы, где пользователь работает.
- Программа **держит буфер обмена открытым** или ломает копирование в других программах.
- Чтение срабатывает на коротких копированиях (пароли, ссылки, отдельные слова).
- Первое чтение «молчит» 9 секунд без какого-либо признака, что программа работает.
- После «Выход» иконка остаётся висеть в трее.

## Поведение

### Запуск и трей

- Один экземпляр: повторный запуск показывает окно уже запущенной копии *(моё решение; допустимо и просто
  завершиться — на усмотрение сборщика, главное — не два экземпляра со слежением за буфером)*.
- При старте окно не показывается, в трее иконка `NotifyIcon`.
- Двойной клик по иконке — открыть окно. Меню иконки: «Открыть», «Пауза/Продолжить», «Стоп», «Настройки…», «Выход».
- Крестик в окне прячет окно в трей; полностью закрывает только «Выход».
- Во время чтения иконка (или её подсказка) меняется, чтобы было видно, что идёт чтение.

### Главное окно

- Многострочный `TextBox` с прокруткой; «Озвучить» читает его содержимое (*моё решение:* Ctrl+Enter — то же самое).
- «Пауза/Продолжить» и «Стоп» активны только во время чтения.
- Пустой текст — «Озвучить» ничего не делает.

### Буфер обмена

- Слежение через `AddClipboardFormatListener` / `WM_CLIPBOARDUPDATE` (окно с handle существует и в свёрнутом
  состоянии, или скрытый `NativeWindow`).
- Берётся только текст. Слова — разбиение по пробельным символам без пустых элементов.
  Условие: `слов > N`.
- **Новый длинный текст прерывает текущее чтение** и начинает новый (согласовано с пользователем).
- *Моё решение:* если пришёл тот же текст, что **читается прямо сейчас**, — игнорировать (некоторые программы
  шлют несколько `WM_CLIPBOARDUPDATE` на одно копирование, иначе чтение будет перезапускаться). Когда чтение
  закончилось или остановлено, повторное копирование того же текста снова его читает.
- *Моё решение:* копирование во время паузы — то же, что во время чтения: новый длинный текст прерывает паузу и читается.
- *Моё решение:* «Озвучить» в окне прерывает любое текущее чтение, включая автоозвучку.
- *Моё решение:* автоозвученный текст **не** вставляется в поле ввода (чтобы не затереть набранное).
- Буфер может быть занят другой программой (`ExternalException`) — пропустить событие, не падать.
- Автоозвучку можно выключить в настройках.

### Окно настроек

- Список голосов, сгруппированный «Silero» / «Microsoft»; голоса прочих сторонних движков (если появятся) —
  в группу «Другие» *(моё решение)*. Реализация — например, `ListView` с `Groups` или owner-draw `ComboBox` —
  на усмотрение сборщика). Кнопка «Прослушать» читает короткую фразу выбранным голосом *(моё решение)*.
- Скорость: `Rate` −10…10. Громкость: `Volume` 0…100.
- Порог N: `NumericUpDown`, минимум 1, по умолчанию 100.
- Галочки: «Читать длинный текст из буфера», «Запускать вместе с Windows» (ключ `HKCU\...\Run`).
- Кнопка «Настройки Silero…» запускает `C:\Program Files\SileroTTS\bin\silero_tts_config.exe`
  (путь лучше вывести из реестра/токена; если утилиты нет — кнопка скрыта).
- Кнопки внизу справа: «Отмена», затем «Сохранить» крайней справа (конвенция пользователя).
- Настройки — JSON в `%APPDATA%\TtsTray\settings.json` *(моё решение: рядом с exe нельзя, если программа в
  Program Files)*. По умолчанию голос — первый Silero с культурой ru-RU, иначе первый доступный.

### Ошибки и крайние случаи

- Сохранённый голос исчез (Silero удалили) — взять голос по умолчанию и показать уведомление у трея.
- Голосов нет совсем — сообщение, «Озвучить» недоступна.
- Холодный старт Silero (~9 с): прогреть выбранный голос в фоне после запуска и после смены голоса; пока прогрев
  или первая загрузка не закончились, показывать состояние «Загрузка голоса…». Способ прогрева — на усмотрение
  сборщика, критерий — первое чтение после старта программы звучит без заметной задержки, если с момента запуска
  прошло > 15 с.

## Технические решения

- .NET 10 WinForms, `net10.0-windows`, `<UseWindowsForms>true</UseWindowsForms>`, **`<PlatformTarget>x64</PlatformTarget>`**
  (движок Silero зарегистрирован в 64-битном разделе реестра).
- SAPI — только через COM `SAPI.SpVoice` (`Type.GetTypeFromProgID` + `Activator.CreateInstance` + `dynamic`).
  **Не** `System.Speech` (с Silero выдаёт тишину), **не** `<COMReference>` (не нужен, `dynamic` проверен).
- Полезные константы SAPI: `SVSFlagsAsync = 1`, `SVSFPurgeBeforeSpeak = 2` (прервать текущее), `SpVoice.Pause()` /
  `Resume()`, `Status.RunningState` (`SRSEDone = 1`, `SRSEIsSpeaking = 2`), `GetVoices()` → токены с `Id` и
  `GetDescription()`.
- `SpVoice` создаётся и вызывается в UI-потоке (STA). Окончание чтения — опросом `Status.RunningState` по таймеру
  WinForms или событиями COM — на усмотрение сборщика; главное — не блокировать UI-поток `WaitUntilDone`.
- Стиль кода — по глобальным правилам пользователя: комментарии на русском, приватные поля без `_` и с `this.`,
  без лишних private-методов-помощников, без интерфейсов с одной реализацией.

## Тесты

Автотестов нет (решение пользователя). Проверка — только ручная приёмка ниже; логика остаётся в обработчиках форм.

## Приёмка (на этой машине, руками)

1. Запуск → окна нет, иконка в трее.
2. В окне набрать текст, выбрать `Zinaida (Russian)` → звучит. Выбрать `Microsoft Irina Desktop` → звучит.
3. Скопировать в Блокноте ~150 слов → чтение началось, Блокнот остался в фокусе.
4. Скопировать ~50 слов → тишина. Поставить порог 40 → те же 50 слов читаются.
5. Во время чтения скопировать другой длинный текст → старое оборвалось, читается новое.
6. Пауза/Продолжить/Стоп из окна и из меню трея.
7. Изменить скорость/громкость/голос, перезапустить программу → настройки сохранились.
8. «Выход» → процесса нет, иконки в трее нет.

## Оставлено сборщику

Имена классов и файлов, раскладка формы, способ группировки списка голосов, способ отслеживания окончания чтения,
способ прогрева, иконки (можно из `SystemIcons`), формат подсказок трея.
